# 首次上电与真机接入

到目前为止，**没有任何一行代码在真实硬件上运行过**。所有验证都基于固件核心加仿真机械臂，部分参数和别人在真机上测的数据对过。本文是把系统接到真机时的检查顺序，每一步都要通过才能进入下一步。

风险最高的部分放在最后：第 5 步之前，机械臂都不会被上电驱动。

## 1. 板子本身（不接机械臂）

1. 不插 USB，用万用表确认：`+5V`、`+3V3` 和 GND 之间不短路；四个 `ISO_GND` 彼此不通，也都不和 GND 相通。
2. 插 USB。测 `+3V3` 为 3.3 V；每路隔离侧 `ISO_5V` 为 5 V，UART 路的 `ISO_3V3` 为 3.3 V。
3. 测 USB 电流。第一版的估算是 320 mA（见 `hardware/sync-controller/docs/selection.md`），明显偏高就断电查。
4. 烧录固件。按住 BOOT 再按 RESET，进入 ROM 的 USB DFU 模式：

   ```bash
   uv run python tools/fetch_firmware_deps.py
   uv run python tools/build_firmware.py stm32
   dfu-util -a 0 -s 0x08000000:leave -D firmware/build/stm32g4/rac_controller.bin
   ```

5. 电脑应出现名为 `RAC Sync Controller` 的串口，RUN 灯约每秒闪烁一次。

## 2. 急停链路（仍不接机械臂）

这一步最重要，不要跳过。

1. 把外接急停按钮的两组常闭触点接到 ESTOP 端子。没接的时候板子应一直处于急停状态，这是设计行为。
2. 用万用表测 RELAY 端子的 `A COM` 和 `A NO`：按钮松开且固件运行时应导通。
3. 按下急停：继电器应立刻释放。松开后，按住 RESET 再看一次：MCU 复位时继电器也必须释放。
4. 断开任意一根急停线：效果应和按下按钮相同。
5. 在网页上确认：按下时显示“急停已按下”，松开后显示等待复位，点复位才恢复。

## 3. 通信与读数（机械臂上电，但不使能）

1. **先用万用表确认 Star 舵机线的线序**。板子的假设是 PH2.0 第 1 针为数据、第 2 针为 12 V（板上悬空）、第 3 针为地。这个线序没有用实物核对过。
2. 机械臂接各自的电源，CAN 总线末端插上 120 Ω 跳线。
3. 运行 `uv run rac up --uri usb://`，打开网页，点“发现”。这一步只读取，不会使能电机。
4. 确认每个端口都识别到正确的型号，在线数为 7/7。Star FL 和 LD 无法自动区分，需要手动选择。
5. 用手转动关节，确认读数变化。此时**机械臂会因重力下落，请先托住**。

如果发现 RS 电机没有回应：`rac_core` 默认用私有协议，电机若工作在 MIT 协议，发现结果中的方言会显示 `RS_MIT`，绑定时需要选对应的方言。

## 4. 校准

对每台臂做：零位、方向、范围、夹爪。

- **零位。** reBot 是静止姿态（URDF 全零）。Star 主臂摆成 [Seeed Wiki](https://wiki.seeedstudio.com/cn/rebot_arm_b601_rs_lerobot/) 的校准姿态，并闭合夹爪。主从映射的偏移是 0，靠的就是两边的零位姿态对应。
- **方向。** 默认都是 +1，一般不用改：真机数据显示 reBot 电机方向和 URDF 一致，Star 舵机方向也和模型一致。逆运动学、重力补偿和映射预设都依赖这一点，所以只有实物确实和模型不符时才改，改了要记下来。
- **范围。** Star FL 的默认范围取自 URDF，只有 ±90°，比实际行程小，跟随时会被提前限位。要用完整行程就做一次范围采集。
- **夹爪。** 主臂的默认行程是 60°（官方脚本的值），请以实际采集为准。

## 5. 第一次运动（空载、低速、手放在急停上）

1. 把速度限制调低。`packages/rac-link/src/rac_link/robots.py` 中默认 1.5 rad/s，首次建议 0.3 rad/s。
2. 只对一台从臂做“校准”页的逐关节验证（幅度 0.1 rad）。如果方向错了，这里能以最小代价发现。
3. **手扶模式第一次开启时，一只手托住机械臂。** 重力计算已经和别人在 B601-RS 上测的数据对过（比例 0.95 至 1.00，符号正确，见 `tests/test_kinematics.py`），但那是另一台臂，你的夹爪和负载可能不同。如果力矩方向错，它会向上或向下加速。
   试的时候让关节离开桌面和其他连杆，比如 J2≈0.7、J3≈1.1。夹爪碰到桌面时的手感不能说明重力补偿的好坏，原因见 `docs/reference/gravity_calibration_rs_2026-07-17.md`。每个关节还有 0.2 至 0.5 N·m 的摩擦，腕部关节尤其明显，这是正常的。
4. 确认一键停止、通信中断（拔 USB）时都能保持或阻尼，而不是下坠。

## 6. 主从跟随

1. 用“相对跟随”，从臂不会跳到主臂的位置。先不要勾选跟随夹爪。
2. **逐关节核对方向。** 预设来自 Seeed 的集成，和 LeRobot 的表、两个模型的关节轴都吻合，但还没在这套系统上跑过。先小幅动 J6，再依次动 J5 到 J1，最后单独试夹爪。
3. 确认同步周期和延迟与仿真接近（reBot 从臂 4 ms 周期，延迟约 10 ms）。Star FL 作为从臂时，每条指令是一次 100 ms 的移动，所以会慢约 100 ms。
4. 快速掰动主臂时不应触发“主臂读数突变”。如果触发，说明读数有问题，先查零位和连接。

## 已知的未验证假设

| 假设 | 风险 | 如何核对 |
| --- | --- | --- |
| RS 型号与关节的对应（1-3 为 RS06，4-7 为 RS00） | 增益和范围错误 | 上游配置如此，用电机读回型号确认 |
| Star 舵机 1 Mbit/s，线序如上 | 无通信 | 第 3 步 |
| 跨型号映射预设。来自 Seeed，但 Digital Twin 的主臂功能自己也写着未经真机验收 | 跟随方向错 | 第 6 步 |
| 位置、跟随和手扶增益，来自 Digital Twin 和 Seeed，换了固件调度可能要微调 | 振荡 | 第 5 步低速观察 |
| 固件在 STM32 上的外设配置（FDCAN、USART、USB、时钟） | 整体不工作 | 第 1 至 3 步 |
| 重力系数来自别人的臂和夹爪 | 手扶时漂移 | 第 5 步 |
| Star 模型的两处修正（FL 的 J4、LD/HD 的 J5）是推断的，只影响 3D 视图和 FL 的逆运动学 | 3D 视图方向不对 | 第 3 步对照实物，改 `tools/import_star_urdf.py` |
| Star FL 的指令参数（100/50/50 ms）来自官方脚本，只在它的调用频率下用过 | FL 跟随偏慢或抖动 | 第 6 步 |

Star HD 的按钮板（舵机 ID 7，用来锁定和解锁主臂）只在发现时识别型号，按钮功能还没有实现。
